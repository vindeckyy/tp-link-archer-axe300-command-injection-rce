--- 3. A/B slots and rollback metadata ----------------------------------------------

Inside the "image" UBI, volumes 1..6 are the slots:

    ubi0_1  metadata1   static    ubi0_2  metadata2   static
    ubi0_3  bootfs1     static    ubi0_4  rootfs1     dynamic
    ubi0_5  bootfs2     static    ubi0_6  rootfs2     dynamic
    ubi0_10 data        dynamic

Both metadata volumes hold the standard A/B selection record:

    COMMITTED=1
    VALID=1,2
    SEQ=3,2

i.e. slot 1 is the committed boot slot, slot 2 is still valid and carries the older
sequence number. That is the rollback target: a slot that fails to boot leaves a
valid, older image to fall back to.


--- 4. Mount points and volatility --------------------------------------------------

    /dev/ubiblock0_4  /        squashfs  (ro)     slot 1 root, read-only
    ramfs             /etc                (rw)     VOLATILE
    ramfs             /usr/lib/lua        (rw)     VOLATILE
    ramfs             /www/tmp            (rw)     VOLATILE
    ramfs             /overlay            (rw)     VOLATILE (overlayfs is NOT used)
    tmpfs             /tmp                (rw)     VOLATILE
    ubi:data          /data               (rw)     persistent
    ubi1:tp_data      /tp_data            (rw)     persistent
    ubi2:user_data1   /user_data1         (rw)     persistent
    ubi2:user_data2   /user_data2         (rw)     persistent

This is the single most important operational fact for anyone modifying this
firmware: /etc is a ramfs, so edits to it, to /usr/lib/lua and to /www are lost on
reboot. Durable state goes in /data, /tp_data or /user_data1-2.

/data also holds the boot environment copies:

    /data/.kernel_nvram.setting    40 KB
    /data/.user_nvram.setting       32 KB
    /data/boot_state_0              18 bytes

--- 6. The vendor's own firmware-upgrade path ---------------------------------------

Web UI -> /usr/lib/lua/luci/controller/admin/firmware.lua -> model/fmup.lua:

    local ret = sys.fork_call("nvrammanager -c \"%s\" > /dev/console" % (firmware_file))
    if ret == 0 then
        debug.printf("firmware check OK")
        ...
        sys.fork_exec("/sbin/sysupgrade \"%s\"" % (firmware_file))

/sbin/sysupgrade is the stock OpenWrt upgrade script. Its platform hook is:

    /lib/upgrade/platform.sh
        platform_check_image() { echo "Platform image check OK ..."; return 0; }
        platform_do_upgrade()  { ...; nvrammanager -u $@; }

Note that platform_check_image() is a no-op: the model checks the image with
"nvrammanager -c" before calling sysupgrade, but sysupgrade on its own does not.
The nvrammanager check enforces a supported-model list ("nm_checkSupportList",
"Firmwave supports / not supports") and rejects downgrades ("nm_checkSoftVer",
"software version dismatched").


--- 7. Bootloader verification and its bypass lever ---------------------------------

The bootloader partition contains the strings:

    signature   verify   decryption   test_mode   test_mode=enable   test_mode=disable

and the kernel command line carries test_mode=disable, i.e. the shipped image is
verified at boot. "test_mode=enable" is present in the same binary, and the
environment it lives in is writable from userspace (see section 4). The practical
consequence: replacing the root filesystem needs either a bootloader path that
accepts an unsigned image, or the serial console.

For reference, the stock OpenWrt tree does carry a target for this SoC family:

    target/linux/bcm4908/Makefile
        BOARDNAME:=Broadcom BCM4908 (ARMv8A CPUs Brahma-B53)
        FEATURES:=squashfs nand usb gpio
        CPU_TYPE:=cortex-a53
        SUBTARGETS:=generic

but no device port exists for the Archer AXE300, and the vendor's datapath
(bcmenet, bcmtm, bluetopia, the WLAN driver) is closed, so a stock image would not
bring working wireless or broadband.
